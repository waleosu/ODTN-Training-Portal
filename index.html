ODTN Telecom: Incident Response Training Portal

A practice exercise. ODTN Telecom is fictional. No data is collected or sent anywhere.

1. Briefing

ODTN Telecom, a fictional carrier, sees a service disruption that gradually looks like a suspected cyber attack. Teams from across the company must work through it together.

  • A plan is not enough. Plans must be practised so people learn what can go wrong and where to improve.
  • Technical teams watch logs, software updates and unusual device behaviour, not just whether devices are online.
  • Communication matters. Staff, the board and the public need timely, accurate updates.
  • Legal and compliance join early so federal and provincial responsibilities are met.
  • The board guides decisions during the incident and reviews security investment afterwards.
  • Cyber security is not only an IT job. A delay or misunderstanding can make things worse.

4. Write the staff update

It is 04:30. Staff are asking what is going on. Write a short update (max 280 characters). It should say what is happening, what you are doing, and when the next update comes. Avoid guessing or false reassurance.

5. Scorecard and security notes

How this site was hardened

  • Static page: no backend, database, login, API keys or AI calls.
  • Strict Content Security Policy; no external scripts, fonts or images.
  • All text you type is length-limited and displayed with textContent, never innerHTML.
  • Nothing is stored in cookies or browser storage, or transmitted.

Remaining risks

  • Hosting settings (HTTPS, security headers) depend on the host.
  • Anyone can read and copy the source, so it must never hold secrets.
  • The text check is keyword-based and can be fooled; it is teaching feedback, not a real control.
